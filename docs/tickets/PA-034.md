# PA-034: Set measured browser and scan resource budgets

Stage: [S4 - Real isolated browser scans](../roadmap.md#s4-real-isolated-browser-scans)
Status: Not started
Depends on: [PA-009](PA-009.md)

## Expected result

Turn the provisional browser limits into explicit enforceable defaults before production scanner integration.

## Scope

- Use PA-026/PA-027 evidence to select numeric per-scan time, memory, transfer/download, concurrency, and relevant artifact/result size limits with units and scope.
- Map each budget to its enforcement layer, configuration key, breach error, process cleanup, and partial-result behavior; identify unsupported enforcement as a blocker.
- Reconcile execution limits with PA-033 lease/retry/deadline policy and define a small reproducible workload for boundary tests.

## Acceptance criteria

- [ ] Each required budget has a finite value, unit, rationale, enforcement mechanism, and expected over-limit result; no required budget remains TBD.
- [ ] Normal controlled mobile/desktop runs fit the initial defaults or the documented scope explicitly explains the constraint.
- [ ] Timeout, worker claim, browser cleanup, and result-delivery policies cannot create unbounded overlapping executions.

## Verification

- Measure the controlled fixture workload using the proof harness and record conditions alongside selected defaults.
- Exercise limit boundaries and review timing/configuration relationships with the delivery policy; record observed limits without promising universal page coverage.

## Out of scope

Integrating the full production runner, request quotas, autoscaling, and load testing unrelated to the first release.

## Completion evidence

Not implemented. Record decisions/artifacts, exact commands and observed outcomes, and any unresolved blocker here. Planned checks do not count as proof.
