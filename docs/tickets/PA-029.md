# PA-029: Implement authenticated service transport

Stage: [S1 - Contract and development flow](../roadmap.md#s1-contract-and-development-flow)
Status: Not started
Depends on: [PA-028](PA-028.md)

## Expected result

Exchange validated fixture messages between two independently runnable services over an authenticated transport.

## Scope

- Select the minimum transport and service identity mechanism compatible with PA-025/PA-026 constraints; document configuration and credential handling.
- Add only application/scanner entry points required to validate and exchange a deterministic fixture using PA-028 schemas.
- Reject unauthorized and unsupported requests, bound transport waits, and map unavailable-peer errors safely. Keep real credentials out of examples and logs.

## Acceptance criteria

- [ ] Authenticated valid traffic crosses the actual process boundary and validates on both sides.
- [ ] Missing/invalid service identity, malformed payloads, and unknown contract versions fail with safe errors.
- [ ] Unavailable peers do not hang forever; required credentials/configuration cannot be silently omitted in a production configuration.

## Verification

- Run two-service integration checks for accepted and rejected messages and peer outage.
- Inspect examples/logs for credentials and record startup/authentication configuration and the finite transport timeout.

## Out of scope

Browser user sessions, job queues, raw page execution, and additional service abstractions.
