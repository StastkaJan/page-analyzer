# PA-027: Prove engine evidence and comparison feasibility

Stage: [P0 - Feasibility and initial decisions](../roadmap.md#p0-feasibility-and-initial-decisions)
Status: Not started
Depends on: [PA-026](PA-026.md)

## Expected result

Use real controlled scan output to establish which report and comparison claims the initial engine can support.

## Scope

- Run the chosen Lighthouse version with the proven harness for both profiles, retaining sanitized output, engine/browser versions, and conditions from controlled page variants.
- Trace actual fields for category scores, audit outcomes, evidence/targets, missing/manual/not-applicable checks, and error states to the proposed domain contract.
- Build a representative comparison evidence matrix for a persistent issue, fixed issue, introduced issue, removed target, missing coverage, and changed profile/version. Identify where target coverage is insufficient.
- Record supported cases and conservative unverified fallbacks. Distinguish captured real output from synthetic fault fixtures and update specs if their promised behavior is unsupported.

## Acceptance criteria

- [ ] Every initial contract field needed by the report has an observed source or an explicit unavailable representation; sample data does not masquerade as real measurements.
- [ ] At least one controlled case each supports persistent, resolved, and new classification with cited coverage evidence; unsupported cases are explicitly unverified.
- [ ] If the committed first-version comparison cannot be demonstrated, the ticket remains blocked pending a supported design or explicit scope decision rather than silently weakening acceptance.
- [ ] Sanitized reusable fixtures and expected outcomes exist with their provenance and reproduction commands.

## Verification

- Reproduce controlled variants and inspect actual engine output for both profiles.
- Walk the evidence matrix against the comparison contract and record capabilities/limitations without inventing an engine guarantee.

## Out of scope

Production scanner integration, general-purpose comparison code, artificial engine fields, and adding another engine solely to fill a speculative gap.

## Completion evidence

Not implemented. Record decisions/artifacts, exact commands and observed outcomes, and any unresolved blocker here. Planned checks do not count as proof.
