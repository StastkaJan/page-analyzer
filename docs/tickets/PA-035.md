# PA-035: Specify URL identity and the comparison decision matrix

Stage: [S6 - Rescan, history, and comparison](../roadmap.md#s6-rescan-history-and-comparison)
Status: Not started
Depends on: [PA-015](PA-015.md), [PA-027](PA-027.md)

## Expected result

Make same-page matching and change classification deterministic before building history and comparison.

## Scope

- Define/version URL identity including meaningful queries, fragments, redirects, and requested versus final URLs using explicit examples.
- Use PA-027 evidence and PA-013 normalization to define rule/target matching and compatible-coverage decisions for supported audit types.
- Write input/expected-output cases for persistent/resolved/new/unverified, missing/manual/failed coverage, removed targets, and profile/engine/condition changes.

## Acceptance criteria

- [ ] Meaningfully different pages are not silently merged; invalid comparison pairs have defined safe rejection behavior.
- [ ] Every supported classification has explicit evidence requirements; unsupported coverage maps to unverified rather than an assumed pass.
- [ ] The matrix includes all four classifications and compatibility warnings, with versioning rules and no identity dependence on recommendation text or measured values.

## Verification

- Review the matrix against the real-derived proof fixtures and the domain contract.
- Convert the agreed examples into data suitable for PA-017 regression checks; record any blocked promise rather than weakening it implicitly.

## Out of scope

Comparison API/UI implementation, scheduled scans, and modifying original reports to improve match rates.
