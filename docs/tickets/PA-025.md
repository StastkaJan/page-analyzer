# PA-025: Select the initial stack and deployment constraints

Stage: [P0 - Feasibility and initial decisions](../roadmap.md#p0-feasibility-and-initial-decisions)
Status: Not started
Depends on: None.

## Expected result

Record a concrete candidate stack and reproducible route to the feasibility checks before building application services.

## Scope

- Inspect the developer environment and choose supported runtime, frontend, package manager, browser runner, and test tools using official documentation at execution time.
- Record the local OS/container needs and intended deployment class, including whether it can enforce browser isolation, egress controls, and resource limits. Hosted vendor procurement is not required.
- Write the selected versions, rationale, minimal commands needed for the proof harness, and known constraints in implementation notes. Decisions remain provisional until PA-026 and PA-027 pass.

## Acceptance criteria

- [ ] The record names actual technologies/versions and an available way to run the proof harness; no required prerequisite is left as an unexplained TBD.
- [ ] Local and deployment constraints are explicit, including any unsupported platform capability and a concrete next action.
- [ ] The first proof check can be run from the documented setup; a missing required environment is reported as a blocker rather than assumed available.

## Verification

- Check installed/prerequisite tools and execute the minimal runner setup/smoke command.
- Review compatibility against current primary documentation and record which conclusions are observed versus still provisional.

## Out of scope

Application scaffolding, selecting every later backing service, paid provisioning, and claiming feasibility from documentation alone.

## Completion evidence

Not implemented. Record decisions/artifacts, exact commands and observed outcomes, and any unresolved blocker here. Planned checks do not count as proof.
