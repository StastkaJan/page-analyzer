# PA-010: Enforce scanner isolation and public-only egress

Stage: [S4 - Real isolated browser scans](../roadmap.md#s4-real-isolated-browser-scans)
Status: Not started
Depends on: [PA-034](PA-034.md)

## Expected result

Integrate the proven isolation/egress mechanism into the scanner worker and enforce recorded budgets before product users can submit arbitrary URLs.

## Scope

- Integrate PA-026's proven connection-time public-only egress for both IP families, initial navigation, redirects, DNS changes, and subrequests into the actual worker.
- Isolate browser processes from application secrets/internal services and enforce PA-034's numeric time, memory, transfer/download, and concurrency budgets.
- Document the enforceable mechanism and safe failure behavior; reject unclassifiable destinations.

## Acceptance criteria

- [ ] Private/local/metadata destinations are blocked through alternate address forms, DNS changes, redirects, and browser subrequests.
- [ ] A controlled public target is reachable with the same boundary enabled; preflight DNS alone is not the protection.
- [ ] Budget exhaustion stops browser work and secret/internal-service access is unavailable to the browser.

## Verification

- Reuse PA-026's boundary checks against the integrated worker, covering IPv4/IPv6, DNS changes, redirects, alternate forms, and subresources; a harness-only pass is insufficient.
- Exercise each resource limit and record the actual isolation/network configuration; use controlled targets outside protected networks.

## Out of scope

Enabling public URL submission before these checks pass and choosing additional audit engines.
