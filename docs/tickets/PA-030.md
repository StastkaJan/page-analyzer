# PA-030: Define user identity and session behavior

Stage: [S2 - Private persisted scans](../roadmap.md#s2-private-persisted-scans)
Status: Not started
Depends on: [PA-003](PA-003.md)

## Expected result

Specify how a real browser user obtains, retains, and loses access to private scans before building persistence.

## Scope

- Choose the minimum first-version identity model, such as managed sign-in or an explicitly described private-session model, and document the user entry/re-entry experience.
- Define session creation, expiry, logout/revocation, ownership mapping, account/session loss behavior, and cross-device expectations; specify numeric session lifetimes.
- Define browser credential storage and relevant cookie/origin/CSRF or token protections for the selected model, plus expired-session UI/API behavior. Avoid a custom password system when a supported mechanism suffices.

## Acceptance criteria

- [ ] Ownership derives from verified identity/session data, never a caller-selected owner ID or scan ID.
- [ ] Initial access, refresh/re-entry, expiry, logout/revocation, and inaccessible-history behavior have explicit expected outcomes.
- [ ] Numeric session lifetimes and storage/protection settings are recorded; unsupported cross-device/recovery behavior is stated without adding speculative account features.

## Verification

- Walk the submission/report/history/deletion journeys for new, valid, expired, revoked, and unrelated sessions.
- Record a decision table that PA-031 can implement and test without selecting another identity model.

## Out of scope

Implementing authentication, team accounts, billing, or promising account recovery that the chosen model does not provide.
