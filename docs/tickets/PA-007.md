# PA-007: Dispatch scans to the queue and show persisted progress

Stage: [S3 - Background execution and recovery](../roadmap.md#s3-background-execution-and-recovery)
Status: Not started
Depends on: [PA-033](PA-033.md)

## Expected result

Accept work quickly and execute it through the queue without blocking web requests.

## Scope

- Implement PA-033's selected queue/result transport and recoverable dispatch, using its authenticated delivery, executable validation, and numeric timing policy.
- Persist queued work and publish jobs with scan/attempt identity; use a single eligible execution claim.
- Connect the fixture worker and result path and display persisted states/timestamps in the interface.

## Acceptance criteria

- [ ] Submission returns a reference before fixture execution completes; refresh does not create work.
- [ ] Transient publish failure recovers or reaches a documented deadline failure, never an indefinite queued scan.
- [ ] Repeated job delivery cannot create unbounded simultaneous executions; malformed/unauthenticated jobs are rejected.

## Verification

- Delay execution and fail queue publishing to check responsiveness and reconciliation.
- Replay a job and send rejected payloads; verify claim ownership and accurate progress.

## Out of scope

Real browsers, unbounded retries, and percentage progress estimates.
