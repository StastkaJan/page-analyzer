# PA-001: Connect the validated services to fixture execution

Stage: [S1 - Contract and development flow](../roadmap.md#s1-contract-and-development-flow)
Status: Not started
Depends on: [PA-028](PA-028.md), [PA-029](PA-029.md)

## Expected result

Complete the fixture execution path over the established authenticated service transport without selecting a new stack or contract.

## Scope

- Connect the validated application request to the scanner fixture adapter and return its response using PA-028 schemas and PA-029 transport.
- Reuse PA-027's evidence mapping for deterministic completed, partially completed, and failed examples, with explicit simulation provenance.
- Preserve scan/attempt/profile metadata and safe errors through the complete call; keep real browser execution unavailable in the application.

## Acceptance criteria

- [ ] All three fixture outcomes cross both services with correct contract version, identity, coverage, and profile metadata.
- [ ] Rejected input and unavailable-scanner errors propagate safely through the application without generating fabricated successful results.
- [ ] The fixture adapter is explicitly development/test-only; both services remain independently runnable with existing authentication.

## Verification

- Exercise each fixture outcome through both services and compare the response to the known fixture.
- Verify unsupported/malformed input, unavailable scanner, and production fixture guards; record exact commands and outcomes.

## Out of scope

Stack selection (PA-025), feasibility proofs (PA-026/PA-027), schema implementation (PA-028), transport/authentication implementation (PA-029), UI, database, and queue.
