# PA-008: Accept results atomically and reject stale or conflicting delivery

Stage: [S3 - Background execution and recovery](../roadmap.md#s3-background-execution-and-recovery)
Status: Not started
Depends on: [PA-007](PA-007.md)

## Expected result

Make result processing safe under duplicate and out-of-order messages.

## Scope

- Validate authenticated result envelopes and artifact ownership before acceptance.
- Persist report and terminal state atomically and acknowledge only after durable acceptance.
- Handle duplicate results, conflicting accepted payloads, expired attempts, and missing start notifications.

## Acceptance criteria

- [ ] Replaying an accepted result creates no duplicate findings or reports.
- [ ] Conflicting results and stale attempts cannot alter an accepted report or regress lifecycle state.
- [ ] A valid current result is not stranded by a missing/out-of-order start event; commit failure permits safe redelivery.

## Verification

- Replay identical/conflicting/stale results and reorder start/result events.
- Inject persistence failure before acceptance/acknowledgement and verify exactly one durable accepted result after recovery.

## Out of scope

Changing immutable report contents and redefining the result contract for each engine.
