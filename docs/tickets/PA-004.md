# PA-004: Persist owner-scoped scans and immutable reports

Stage: [S2 - Private persisted scans](../roadmap.md#s2-private-persisted-scans)
Status: Not started
Depends on: [PA-031](PA-031.md), [PA-032](PA-032.md)

## Expected result

Retain fixture scan results in the application database with private ownership.

## Scope

- Use PA-031's verified request context and PA-032's database/schema to implement private scan persistence; never accept a caller-selected owner ID.
- Persist scan URL/profile, lifecycle, attempt identity, timestamps, accepted result, and terminal snapshots.
- Authorize scan creation and retrieval in the application; keep database access out of the scanner.

## Acceptance criteria

- [ ] Two distinct principals cannot retrieve each other's scans even when IDs are known.
- [ ] Scan/report data survives service restart and terminal snapshots cannot be overwritten.
- [ ] Statuses and missing values preserve the contract semantics; a failed scan cannot appear as a clean report.

## Verification

- Create fixture scans through two actual independent authenticated sessions, restart services, and verify owner-only retrieval.
- Attempt cross-owner access and terminal-result mutation; verify denial without data corruption.

## Out of scope

Selecting identity/database again, session implementation, schema bootstrap, team accounts, billing, queue infrastructure, and retention automation.
