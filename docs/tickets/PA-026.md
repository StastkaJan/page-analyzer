# PA-026: Prove browser isolation and connection-time egress

Stage: [P0 - Feasibility and initial decisions](../roadmap.md#p0-feasibility-and-initial-decisions)
Status: Not started
Depends on: [PA-025](PA-025.md)

## Expected result

Produce a runnable, bounded proof that the chosen environment can safely execute controlled browser checks before committing to the service architecture.

## Scope

- Build the smallest isolated browser harness with connection-time public-only network enforcement, no application secrets, and finite provisional resource limits.
- Exercise IPv4/IPv6, alternate address forms, redirects, DNS changes, and subrequests against controlled targets. Allow a controlled public page under the same boundary.
- Record the mechanism, provisional numeric limits with units, environment/version information, exact commands, and pass/fail matrix. Preserve reusable checks for PA-010.

## Acceptance criteria

- [ ] Private/local/metadata destinations cannot be reached through the tested navigation and subrequest cases; no preflight-only validation is accepted as enforcement.
- [ ] The public control page loads with the boundary enabled, and the harness demonstrates process isolation and termination under provisional limits.
- [ ] Missing capabilities fail closed; a failed feasibility result records the constraint and blocks dependent work until a workable approach is proven.

## Verification

- Run the real browser boundary matrix with controlled endpoints; do not probe unrelated private services.
- Inspect the browser environment for application credentials and exercise timeout, memory, transfer/download, and concurrency boundaries supported by the proposed deployment.

## Out of scope

Product submission endpoints, queue integration, unrestricted scanning, and treating this harness as the production scanner.

## Completion evidence

Not implemented. Record decisions/artifacts, exact commands and observed outcomes, and any unresolved blocker here. Planned checks do not count as proof.
