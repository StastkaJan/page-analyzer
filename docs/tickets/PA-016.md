# PA-016: Add immutable rescans and private scan history

Stage: [S6 - Rescan, history, and comparison](../roadmap.md#s6-rescan-history-and-comparison)
Status: Not started
Depends on: [PA-035](PA-035.md)

## Expected result

Let an owner request a new measurement while keeping prior reports intact.

## Scope

- Add explicit rescan with a new scan ID and profile selection using the existing execution path.
- Implement PA-035's versioned URL identity policy while preserving meaningful query parameters.
- List owner-authorized scans for the same requested page and select baseline/later scans.

## Acceptance criteria

- [ ] Rescan creates independent work and never mutates the original terminal report.
- [ ] Meaningful URL differences cannot be silently discarded to force a match.
- [ ] History and baseline selection do not leak another user's reports.

## Verification

- Rescan a controlled page and verify both snapshots before/after the new run.
- Exercise URL identity variants, profile selection, refresh, and cross-owner history access.

## Out of scope

Scheduled scans, site crawling, and computing finding differences.
