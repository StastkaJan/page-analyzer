# PA-028: Implement executable scan and result schemas

Stage: [S1 - Contract and development flow](../roadmap.md#s1-contract-and-development-flow)
Status: Not started
Depends on: [PA-027](PA-027.md)

## Expected result

Provide one validated contract with fixtures grounded in the feasibility evidence, independently of service transport.

## Scope

- Implement job/result schemas, supported contract version checks, scan/attempt IDs, profiles, timestamps, source scores, coverage, evidence, and safe error representations.
- Use PA-027's mapping and distinguish missing, zero, not-applicable, manual, skipped, and failed states; retain engine extensions without requiring them for every result.
- Add deterministic valid/invalid fixtures and document schema locations and compatibility behavior in the existing contract documentation.

## Acceptance criteria

- [ ] Completed, partially completed, and failed fixture payloads validate with the correct semantics.
- [ ] Malformed types/IDs, missing required fields, unsupported versions, and inconsistent required outcome data are rejected.
- [ ] Producers and consumers can use the same schema; documents do not become a second contradictory executable definition.

## Verification

- Run schema validation against the real-derived and fault fixtures plus zero/missing score cases.
- Check that examples and contract documentation agree with supported version/rejection behavior.

## Out of scope

Service endpoints, authentication implementation, database, queue, and future version migration infrastructure.
