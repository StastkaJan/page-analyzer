# PA-031: Implement user sessions and authenticated request context

Stage: [S2 - Private persisted scans](../roadmap.md#s2-private-persisted-scans)
Status: Not started
Depends on: [PA-030](PA-030.md)

## Expected result

Establish verified browser identity for private application requests before reports are persisted.

## Scope

- Implement the chosen sign-in/private-session creation, restore, expiry, logout/revocation, and error states.
- Derive an authenticated request context and reject forged identities using the selected credential/session protections.
- Expose minimal interface entry/exit behavior and safe handling of expired sessions; use the selected provider/library rather than a custom identity framework.

## Acceptance criteria

- [ ] Two real independent browser sessions map to distinct verified principals, without testing solely through hard-coded owner IDs.
- [ ] Forged, expired, and revoked credentials cannot authorize application requests; refresh/re-entry behaves according to PA-030.
- [ ] Chosen origin/CSRF or token protections and numeric expiry behavior are enforced without leaking credentials to logs.

## Verification

- Exercise session creation/restore/expiry/revocation with two browser contexts and a controlled clock where appropriate.
- Attempt identity spoofing and the chosen model's relevant browser credential attack cases; record results.

## Out of scope

Database report storage, team permissions, and identity-provider features outside the chosen flow.
