# PA-006: Integrate validated submission and saved report views

Stage: [S2 - Private persisted scans](../roadmap.md#s2-private-persisted-scans)
Status: Not started
Depends on: [PA-004](PA-004.md), [PA-005](PA-005.md)

## Expected result

Allow an owner to submit a fixture scan and reopen its private report after refresh.

## Scope

- Validate HTTP/HTTPS syntax and reject credentials and prohibited literal addresses without navigating.
- Connect submission, status, saved report, and artifact access in the interface using the ownership model.
- Exclude sensitive URL values and content from routine logs and preserve safe rendering and accessible errors.

## Acceptance criteria

- [ ] Invalid submissions receive actionable errors; explicit sample mode remains visible and execution stays fixture-only.
- [ ] Refreshing or reopening a report retrieves the existing scan instead of submitting another.
- [ ] Saved reports remain readable after restart, with safe output and owner-only access throughout.

## Verification

- Exercise invalid URL forms, refresh/restart, two principals, and hostile report text.
- Inspect test logs for sensitive values and demonstrate S2 retrieval with a permitted artifact.

## Out of scope

Connection-time network enforcement, actual navigation, and historical comparison.
