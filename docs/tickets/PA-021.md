# PA-021: Integrate safe diagnostics and operational recovery

Stage: [S7 - Operating limits, retention, and diagnostics](../roadmap.md#s7-operating-limits-retention-and-diagnostics)
Status: Not started
Depends on: [PA-019](PA-019.md), [PA-020](PA-020.md)

## Expected result

Trace and recover failed work without exposing sensitive target data.

## Scope

- Record scan/attempt correlation, queue/execution/delivery timings, outcomes, and resource-limit events with existing platform facilities.
- Document recovery for dispatch, worker, delivery, storage, and cleanup failure using the implemented mechanisms.
- Recheck access control, service authentication, and network isolation during concurrent/failing operation.

## Acceptance criteria

- [ ] An operator can follow a failed scan using IDs and safe error codes without page bodies, secrets, or sensitive URL values.
- [ ] Recovery instructions match actual behavior and do not overwrite terminal data or resurrect deletions.
- [ ] Recorded S7 checks show bounded work, effective deletion, and preserved security boundaries.

## Verification

- Run failure/recovery exercises and inspect diagnostic output for sensitive fields.
- Repeat relevant concurrency/authentication/egress checks and record the operational settings and remaining limits.

## Out of scope

A bespoke observability stack, public deployment, and unproven capacity promises.
