# PA-002: Connect the accessible interface to the fixture flow

Stage: [S1 - Contract and development flow](../roadmap.md#s1-contract-and-development-flow)
Status: Not started
Depends on: [PA-001](PA-001.md)

## Expected result

Let a developer select a sample and see its outcome through both services.

## Scope

- Add known-sample selection and an explicit mobile/desktop profile control.
- Provide completed, partially completed, and failed fixture responses and render their evidence/coverage safely.
- Label the entire flow as a simulation and keep the fixture adapter development/test-only.

## Acceptance criteria

- [ ] All three sample outcomes display correctly through the real service boundary; scanner unavailability produces an actionable error.
- [ ] Keyboard controls have labels and visible focus; hostile sample text renders as text rather than executing.
- [ ] No sample claims the supplied URL was measured, and fixtures cannot silently replace failed real scans.

## Verification

- Exercise each profile and sample outcome plus scanner unavailability.
- Check keyboard navigation, focus, hostile text rendering, and the production configuration guard for fixture mode.

## Out of scope

Persistence, queueing, real measurements, and polished recommendation rules.
